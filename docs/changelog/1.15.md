# Changelog: the 1.15 line

The entries of the 1.15 line, moved here whole from [CHANGELOG.md](../../CHANGELOG.md): nothing was cut or reworded.

## [1.15.0] - 2026-10-06

File lists name each folder once, and every answer speaks one convention
for line numbers: `line` is 1-based, `line0` and `character0` are the
0-based positions the engine tools take. `delphi_list` and `vault_search`
go by pages, and the census of real answers took out what they repeated
(about 40% fewer tokens over ten list calls, measured).

### Changed

- **File lists come grouped by folder.** Every answer that lists files
  writes each folder ONCE, complete and with its virtual drive, and under
  it each file by its name: `<list> = [{dir, files = [{name, ...}]}]`. The
  list keeps its name, and becomes `folders` only where that name would
  repeat inside each folder: the `files` of `delphi_list` and
  `delphi_search`, and the `dirs` of `dirs=true` (the subfolders, names
  under their folder). That covers `delphi_list`, `delphi_search` (the hits
  under each file), `delphi_projects` (`projects`, with no more `project`
  and `dir` on each entry; `name` is now the file name, extension
  included), `delphi_references` (`confirmed`, `unverified`, `mentions` and
  `rejected`, each folder > file > hits), `delphi_rename_symbol`
  (`changes`, `unverified`, `lookalikes`), `delphi_symbols` of a folder
  (`units`), `delphi_test` discover (`projects`: the `.dpr` as `name`
  instead of `project` and `dpr`), `delphi_styles`
  (`lookupsWithoutStyle`) and the packages of `delphi_paserver`. A page
  stands on its own: when a folder carries on
  into the next page, that page names it again. Measured with the Qwen3.8
  tokenizer on real trees, the same calls before and after: a page of
  `delphi_list` went from 34.5k to 16.5k tokens (-52%), a page of the RTL
  -41%, `dirs=true` -82%, `delphi_projects` -19 to -22%, `delphi_search`
  -3 to -15%, `delphi_references` -9%; 40% less over the ten calls. A
  small local model builds the paths from the grouped form as well as from
  the flat one (45 of 45 against 44 of 45 on the same questions).
- `delphi_definition`: each location carries `path` and `line` and no
  longer the `uri` (`file:///srvd%3A/...`) - the same path again, in a form
  no tool takes.
- `delphi_build`: errors, warnings and the output tail no longer end in
  ` [<path of the .dproj>]`. msbuild writes that same path on every line,
  close to 40% of a warning.
- **One convention for line numbers in every answer**: `line` is the
  1-based line `delphi_read` shows; `line0` and `character0` are the 0-based
  positions the engine tools take - as `delphi_search`, `delphi_symbols` and
  `delphi_rename_symbol` already answered. `delphi_references` answered
  `line` 0-based with `line1` beside it and `character`, so the same name
  meant two numbers in two tools that are chained; `delphi_definition` and
  `delphi_diagnostics` said `line1`; `resolvedLine` (where a use resolved
  instead) was 0-based, with a `resolvedLine1` only on rejections. The
  engine's raw `range` stays as LSP sends it. The `line`/`character`
  parameters of the semantic tools (still 0-based, as LSP) now say they
  take a hit's `line0`/`character0`, and `delphi_definition` carries
  `line0` and `character0` too, so a location chains like a hit.
- **Each use carries its line once**: `text` in `delphi_references` and
  `delphi_rename_symbol` is the line as it is, indentation included - the
  anchor `delphi_edit` takes, as in `delphi_search`. It came twice, trimmed
  in `text` and whole in `anchor`.
- `delphi_projects` names each git repository once, in
  `repos = [{dir, branch}]`, instead of `repo` and `branch` on every
  project: a project's repository is the LONGEST `dir` its folder is
  inside (a nested repository or a submodule is its own entry), and
  `delphi_git` takes any path inside it.
- `delphi_diagnostics` no longer repeats `source` (always `DelphiLSP`) and
  an empty `tags` on every diagnostic, and `delphi_paserver platforms` and
  `packages` say `delphiVersion` once at the top instead of on every entry
  (one server, one Delphi): about 15% of each of those answers. Found by a
  census of 24 real calls (Qwen3.8 tokenizer) that looked for what else
  could be slimmed after the file lists; what remains is mostly the fixed
  notes, instructions that go out the same on every call, left for the
  next release with the comprehension bench.
- `filesCount` is the number of files in `delphi_package`, in each pull of
  `delphi_paserver get-sdk` and in the preview of `delphi_changeset`: it
  was `files`, the name every other answer gives a list of files.
- `delphi_rename_symbol` speaks the names of `delphi_references`:
  `filesTouched` is the number of files it touches (`files` was a number
  in the same answer whose lists group their files under `files`),
  `mentionsCount` and `unverifiedCount` are the counts, and `unverified`
  is the list (it was `unverifiedRefs`, and now carries `character0` like
  every change).
- **`vault_search` goes by pages**, like `delphi_search`: `maxresults` per
  page (50, up to 500) and `offset`; the first line says how many there are
  in all, from where, and the offset of the next page. It used to stop at
  the maximum with "(limit reached)" and nothing past it could be reached.
  Each page walks the whole vault to count it, so a regular expression
  the engine gives up on, in a note past the first page, now fails the
  first page too - as in `delphi_search`.
- `__pycache__` is build output (Python's), hidden and counted like a build
  folder by every tool that walks a tree: `delphi_list` in files mode too
  (only `dirs=true` hid it), `delphi_search`, `delphi_projects`, the scan
  of `delphi_references`; naming it as root lists it. Uploading into it
  is refused, as into `Win64` or `__history`.
- **`delphi_list` goes by pages, like `delphi_search`**: 500 entries per
  page (`maxresults` up to 500), with `offset`, `nextOffset` and `hasMore`,
  in both modes (`dirs=true` too). It used to stop at 500 with nothing past
  them reachable: in the reference root of an ERP the first 500 were copies
  under `backups\` and the live project could not be listed (a night report
  from the 13.2 machine). A listing that does not fit also says where its
  entries are (`byFolder`, the folders that hold the most, as
  `delphi_projects` already did), so the next call picks a root instead of
  walking pages.

### Fixed

- **`delphi_diagnostics` of a unit with no project settings answers at
  once**: `LSP-035 NOT_FOUND` - no `.delphilsp.json` or `.dproj` was found for
  it in its folder or the ones above - and says the way out
  (`delphi_config command=add-unit`, or `delphi_create`). It used to answer
  "in progress, call again" forever: with no project settings the engine
  never publishes diagnostics, not even for a syntax error (measured: 4.5
  minutes and 80 seconds), and an agent following the natural flow - create a
  standalone unit, lint it - spent its client's whole timeout and took it for
  a dropped connection (a night report from the 13.2 machine). No engine is
  started for it now. A unit that no project lists but that lives next to one
  is still linted with that project's settings.
- `delphi_build` with a platform in `target` (`target=Win32`): `BUILD-004`
  now says it is a platform and that it goes in `platform=`.
- The startup cleanup of temporary folders walked a root once per workspace
  that declared it: the same network root in two workspaces was walked twice
  (two lines in the log of the 13.2 machine). Each place once now, compared
  the way the jail compares places.
- **A whole Pascal source written from the agent's `content` gets the
  nested-brace warning** (`EDIT-091`): `delphi_create` of a unit or an
  `.inc`, and `delphi_edit createunit` with `content`. Only the edit engines
  gave it, and a unit created with an example of a brace comment inside a
  brace comment did not compile with nothing saying why (this release's own
  new unit, three E2065).
- `delphi_config add-platform`, and the deploy manifest `delphi_build`
  writes into a `.dproj`, took as indentation EVERYTHING before the tag on
  its line: in a hand-edited `.dproj` with `</Platforms>` right after
  another tag, the new entry duplicated that tag (measured: `Win64` twice).
  Now only the blank is copied (one helper for both) and the new entry goes
  right before the tag - the same bytes as before when the tag starts its
  line.
- `delphi_list` with a mask that only matched hidden files (`*.pyc`, all in
  `__pycache__`) said at once "125 are in build folders" and "the mask
  matched nothing". The second note now appears only when nothing was
  hidden. `LIST-003` names `__recovery` too, which it always hid.
- `[Server] DelphiVersion=37,0` - the decimal comma of a Spanish keyboard -
  and `37.00` are read as `37.0`, like `37` already was; the server did not
  start with them. Anything else that is not an installed version still
  stops it, saying why and which keys would work.
- `delphi_test`: the discover note told to build a test `.dpr` that has no
  `.dproj` "with delphi_build on its .dpr", and `delphi_build` takes a
  `.dproj` only; it now says that such a project cannot be built here and
  how to get its `.dproj`. `TEST-005` pointed at a `project` field that the
  answer of `delphi_projects` no longer has.

### Internal

- New battery `test_paredes_1141`, each fix with its mutant red. It also
  keeps that `delphi_config add-unit` takes `unit=` as an alias of `path`, as
  it has since 0.64: the refusal in that report most likely came from the
  client's own bridge, which checks calls before sending them.
- The `BUILD-041` note of `delphi_diagnostics` (a lint with no project
  settings) is gone: that branch can no longer be reached.
- One page of a list (`TPagina`) and one count by folder (`TPorCarpeta`),
  for `delphi_search`, `delphi_projects` and `delphi_list`: the first two
  wrote theirs by hand. The `SEARCH-001` note is gone (it could not be
  reached either).
- `test_paredes_1141` also covers the pages of `delphi_list` and the
  cleanup of a repeated network root (that one needs
  `DELPHI_MCP_TEST_NETDIR`, a folder on a connected network drive).
- One organizer for every list of files: `Lsp.Listas` (`TListaDeFicheros`,
  with `TPagina` and `TPorCarpeta` moved out of `Lsp.References`).
  `AgrupaPorFichero` and `AgrupaPorCarpeta` give a flat list its shape where
  a tool builds it flat inside (the rename consumes references flat). The
  organizer masks the folder: `delphi_search` is an echo tool, outside the
  outbound filter, and without it its folder would leak (measured with the
  mutant).
- The batteries read every list through one reader in `mcp_cliente`
  (`ficheros`, `aciertos`); about 40 batteries moved to it. New battery
  `test_listas_1150`: the shape, a page that names its folder again, a
  folder that reaches the organizer out of order (`delphi_projects` walks
  by mask), `__pycache__` and the pages of `vault_search`, each with its
  mutant red. `test_round8` now builds an error in a unit named by its
  absolute path, so its leak check still has a path to look at;
  `test_rename` checks a definition without `uri`; `test_mudanza` the
  warning of the three creators.
- Three reviewers before the tag (correctness, contract, batteries); every
  theory was measured before changing code, and every fix has its mutant
  red. The shared readers `mc.ficheros` and `mc.aciertos` are STRICT now: an
  entry that still carries its own `path` or `dir`, a group without `dir`,
  or a drive folder without its backslash (`srvq:`, the current folder for
  Windows) fails the battery - flattening blindly, the reader hid exactly
  what `test_raiz_unidad` watches, and two mutants of the organizer passed
  the whole suite. `mc.unicos` checks each folder and each file once.
  Negative checks over a listing got their positive control (a visible
  folder next to the hidden ones), `test_round8` C2 (always true once
  `repo` left the projects) measures `repos`, and `diagnostics` `line` and
  `resolvedLine` are pinned against the lines on disk.
- Measured, nothing to change: DelphiLSP sends no `relatedInformation` in
  its diagnostics, not even for E2037 (a declaration that differs from the
  previous one) or E2065, so `delphi_diagnostics` has no location without
  `path` to convert. `test_workspace_tools` clones this repository by its
  current URL (it used the old name, which GitHub redirects).
