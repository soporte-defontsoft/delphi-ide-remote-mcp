# Changelog: the 1.12 line

The entries of the 1.12 line, moved here whole from [CHANGELOG.md](../../CHANGELOG.md): nothing was cut or reworded.

## [1.12.1] - 2026-10-04

What the live test of 1.12.0 found: the line that opens an object in a form
was read by six regular expressions, and 1.12.0 had fixed one.

### Fixed

- **One reader for `object Name: TClass`.** The lint, `check-binding` (twice,
  plus a third pattern built per field), `tree`/`get` (`Lsp.Styles`), the
  unit rename and `layout` each had their own pattern, with `\w`, which in
  `TRegEx` is ASCII. A component name with an accent (`object lblDirección:
  TLabel`) was read as the class `lblDirecci`, and in `check-binding` an
  unnamed object (`object TMemo`) or an accented name did not count as an
  object while its `end` did: the next component was taken for the form
  itself and never checked. Measured live: a `TComponenteQueNoExiste`
  without a field went unreported. Now one function (`LineaDeObjeto`, in
  `Lsp.DesignerBin`) reads it for all six, and `check-binding` reads the
  published field names of the `.pas` the same way.

### Internal

- The generator's list of the types a `DefineProperties` names takes a `T`
  and an upper-case letter, as a type is named: `True` and `TextHeight` got
  in. The tables' generation goes to 4.
- Measured, no change: a table generated from a process launched by the
  desktop app had another fingerprint than the service's for the same
  source - same 125 folders, same 3,938 units, the same facts in another
  order. That process sees the IDE's library path in another order - most
  likely because the desktop app's package virtualizes the user's registry;
  not confirmed from outside it - and the fingerprint follows the order the
  compiler searches in. Only the service generates the tables it uses.
- Tests: `LaLineaDeUnObjeto` (DUnitX) and `check-binding`/`tree` with an
  unnamed object and accented names (`test_designer`).

## [1.12.0] - 2026-10-04

The designer tables (what `delphi_designer info`, `prop` and the lint answer
from) are read from the source of each installed Delphi, instead of two units
generated from one RAD Studio's RTTI and compiled into the server.

### Changed

- **The designer tables come from the source of the active Delphi.** Until
  1.11 they were `Lsp.DesignerMeta.Vcl/Fmx.pas`, dumped by hand from the RTTI
  of one build and compiled into the exe: with another Delphi, "not in the
  table" stopped meaning "does not exist". Now the server reads the source the
  IDE itself reaches - its Library Search Path and Browsing Path, Win32 and
  Win64, folder by folder like the compiler, includes in subfolders too - with
  its own preprocessor (the conditional symbols are derived from the compiler
  version, never a list per version) and a declarations reader, resolving
  every name in the scope of its unit. Measured against the RTTI tables of
  1.11.3: **100 % of the properties identical** (VCL 7,117, FMX 11,779),
  every enum and set equal.
- **Every class, enumeration and set by its unit.** Two units can declare the
  same name with other members (FireDAC's and IBX's `TIBProtocol`, the VCL's
  `TFont` and TeeChart's): the table keys them with their unit, so a value is
  checked against the enumeration of ITS property and going down a property
  lands on ITS class. The name a form writes (`object X: TFoo`) goes to the
  class a source registers on the palette, then to the installation's over a
  third party's; a form or data module never takes it; when nothing decides,
  that line is not judged (`DSGN-055`).
- **What a class streams by code is known.** The names of its
  `DefineProperties` (`Left`/`Top` of every component, the VCL's `Explicit*`
  and `DesignSize`, `TCustomForm.TextHeight`, `TField.Lookup`, QuickReport's
  `FontSize`, FMX's `Viewport.Width` and `Position.Point`), including those a
  helper reads for the classes that call it (the old FMX `Font.Size`,
  `WordWrap`, `TextAlign` a `TLabel` still loads). The hand-written list the
  lint carried for some of them is gone. `info` lists them in `definedByCode`.
- **Generated in the background, one per installed Delphi, and cached.** At
  startup and whenever the source changes (about 14 s for the 3,938 units of a
  RAD Studio 13 with JVCL, QuickReport and ICS installed from source), into
  `%LOCALAPPDATA%\DelphiLspMcp\designer`, with a fingerprint of that source in
  the file name. Nobody generates a table while asking for it: while a new one
  is generated the previous one answers, `info`/`prop`/`lint` wait up to 30 s
  when there is none, and the lint that follows every edit of a form never
  waits. A failed generation is remembered for 10 minutes instead of being
  retried on every call; the old tables go after an hour.
- **Data components and components installed from source are known.**
  `TFDQuery`, `TDataSource` and whatever the library paths reach now have
  their published properties in `info`, `prop` and the lint (before:
  `DSGN-015`).
- **The lint accepts what a descendant of a property's declared type
  publishes.** The class a class-typed property really holds is chosen by code
  (`TLabel.TextSettings` declares `TTextSettings`, which publishes nothing,
  and holds a `TLabelTextSettings`); going down such a property, a
  sub-property published by any descendant is not denied, and one that no
  class of that family publishes is warned with what they publish. Every
  "runtime class" the old tables recorded (48 VCL, 94 FMX) is covered.
  `delphi_designer prop` no longer answers `runtimeClass`; `info` of a class
  that publishes nothing but has descendants lists what they publish
  (`descendantsPublish`, `DSGN-057`).
- **The root object of a form is never judged**, nor an `inline` frame: they
  are the user's classes, and a demo in the library paths can share the name
  (`TForm1`). An unnamed `object TMemo` is its own object now (its properties
  went to its parent).
- **`delphi_designer` takes the write lock only for `to-text`/`to-binary`.**
  `info`, `prop` and `lint` read, like `delphi_read`.

### Added

- `DSGN-050`: the active Delphi has no source to read, so there is no table -
  the server does not check a form against another version's.
- `DSGN-051`: the table is still being generated after the wait; try again.
- `DSGN-052`: the lint after an edit did not check the form, and why - on its
  own line, and saying the edit is done (never "try again").
- `DSGN-053`: the generation failed, with its reason, and when it is retried.
- `DSGN-054`: the table could not be used (an error reading it).
- `DSGN-055` / `DSGN-056`: a class name two units declare with other
  published properties, and no rule decides which one a form means.
- `DSGN-057`: what the descendants of a class publish.
- `DOCS-016`: a help section that stops at its first sub-heading, and
  `subsections` with the ones that follow.
- `DSGN-058`: the objects the lint could not check (a class not in the
  table, or ambiguous), on their own line and not counted as warnings.

### Removed

- `Lsp.DesignerMeta.Vcl.pas` / `.Fmx.pas` (about 1 MB of tables in the exe),
  the `src/DesignerMetaDump` project and its two dumpers in the group, and the
  `DSGN-049` build note that only existed because the tables belonged to one
  build.

### Fixed

- **`delphi_docs` finds a section by its title as the text shows it.**
  `#Helper Syntax` answered `DOCS-010` (no such section) and the page from
  its start, because the anchor is `Helper_Syntax`; in 826 pages of
  `topics.chm` the anchor is not even the title with underscores
  (`Code_Insight_.28LSP.29_improvements`). The anchor or the title, in any
  case, with spaces or underscores, copied with its `##` too, now finds it,
  and the answer carries the page's anchor (also when the index writes it
  in another case). Found by Hermes in the field.
- **`#Description` of an API page no longer runs to the end of the page.**
  In the API help everything after it hangs from it (`See Also`, `Code
  Examples`, `Exceptions`...: 10,806 pages of `system.chm`, 18,571 of
  `vcl.chm`). A section with no title of its level or higher before or
  after it now stops where its first sub-section starts and lists them in
  `subsections`; one with siblings of its level keeps its sub-sections
  inside, as before. Found by Hermes.
- **`delphi_docs` sections: three more from the review.** The first
  section of a page whose content starts with a title was not found; an
  anchor between the contents box and the first title took the box as its
  section and printed it; and a long page without a contents box (MediaWiki
  puts none under four titles) listed no `sections`. The sections now come
  from the page's titles - one reader for `sections` and for `#<section>`.
- **The lint checks what a class publishes before what it streams by code.**
  FMX `TCustomScrollBox` streams `Viewport.Width`/`Height` with a name built
  from a local constant (`VP + '.Width'`), which the generator read as "any
  name", and the lint asked that first: about 39 FMX classes (`TListBox`,
  `TTreeView`, `TScrollBox`, the grid columns...) accepted any property, and
  the values of the ones they publish were not checked (`Align = alClient`
  on a `TListBox` passed). Published properties come first now, and the
  generator reads a name built from the method's own string constants or
  from a constant list (`OldPropertyNames[I]` of `TColumn`). The author's
  4,234 forms and the 669 of the Samples give the same warnings as before.
- **What the lint could not check is a note, not a warning.** An object of a
  class not in the table or ambiguous (`DSGN-039`/`DSGN-055`) was listed
  after every edit under `EDIT-076` ("the app CRASHES") and counted as a
  warning by `lint` - every edit of a form with ICS's `TSslContext` said so.
  Now it has its own line (`DSGN-058`).
- A component name with accents (`object lblDirección: TLabel`) no longer
  reads part of the name as the class; `info` of a class no longer lists
  the properties of its nested classes (`TGridPanelLayout` showed those of
  `TCellItem`); a global routine no longer lends the names it streams to
  the class of the method before it; a name a helper builds that cannot be
  read is valid only for the classes that use that helper; and a property
  whose type the source does not let us read is `unknown`, not `simple`
  (the lint said it had no sub-properties).

### Internal

- `Lsp.Preproceso` (THE preprocessor: active branches, includes, defines,
  `{$IF}` expressions with `Defined`/`Declared`/`SizeOf`, optionally keeping
  strings), `Lsp.PascalDecl` (the declarations of a unit: classes with the
  visibility of each property, enums, sets, aliases, subranges, nested types
  of classes and records, the arity of generics, escaped identifiers) and
  `Lsp.DesignerMetaGen` (scope resolution, facts, cache, fingerprint, the
  generator's thread). One namer for the identity of a type (`IdDeTipo`) and
  its reader.
- One writer for the server's caches (`EscribeEnCasaDelServidor`, also used by
  the LSP config fabricator; it checks it writes inside the cache folder), one
  namer for the server's cross-process mutexes (`NombreDeMutex`),
  `IdePlatformLibraryPaths` reads the Browsing Path too, `DEFAULT_NAMESPACES`
  shared by its two readers.
- Four independent reviewers before the tag; every finding measured. A port
  of the lint over real forms found what the unit checks could not: 230 wrong
  warnings in the RAD Studio Samples and 2,121 in the author's projects,
  before. After: none in the Samples (six lines of the family warning in one
  of them, kept by decision), and
  in the author's forms the warnings left are properties those components no
  longer have.
- Two more reviewers before the tag, on what came after the first four (the
  fixes from the forms, the help sections): their findings above, each fix
  with its test seen red with the fix removed. One table key composer
  (`ClaveProp`, with a `|` no identity or name contains) and the two other
  readers of a type identity (`EsIdDeTipo`, `UnidadDeIdDeTipo`); the tables'
  generation goes to 3, so no table of the earlier rules is reused.
- DUnitX compares strings ignoring case by default (`Assert.AreEqual`,
  `Contains`, `StartsWith`...): a test of "the page's anchor, not the one
  typed" stayed green with its fix removed. The runner sets
  `Assert.IgnoreCaseDefault := False` once; all 232 tests still pass.
- Tests: `LspTests.DesignerMetaGen` (23 DUnitX tests, each rule with its real
  case; every fix mutated and seen red), `tests/test_designer_tablas.py` (what
  an agent sees, in a cache of its own: the edit note, the previous table
  answering, the purge) and `tests/test_designer_corpus.py` (the lint over the
  Samples).
