# Changelog: the 1.6 line

The entries of the 1.6 line, moved here whole from [CHANGELOG.md](../../CHANGELOG.md): nothing was cut or reworded.

## [1.6.2] - 2026-09-27

### Fixed

- **A request without a valid token got a bare 401** (issue #4):
  `{"error":"missing or invalid bearer token"}` and nothing about how to
  send one. The body now carries a `hint`: the `Authorization: Bearer
  <token>` header, that the token is the `Token=` (or `ReadOnlyToken=`) of a
  `[Workspace.<name>]` section in the `settings.ini` next to the exe, and
  that a browser cannot send it. One text, `SR_TOKEN_NEEDED`, for the two
  401s of the HTTP handler (they were two copies), the tray and the
  no-credentials startup warning. `test_http_auth` checks that the body is
  JSON and says it.
- **The tray's *Copy server URL* copied a URL that only answers 401.** It now
  shows, in a balloon and in its log, what a client has to send with it -
  the same text. The README and the QUICKSTART say it too: the bare URL,
  in a browser for instance, always answers 401.

### Changed

- **The tray speaks English** (issue #3): its menu (*Status / Log*, *Copy
  server URL*, *Exit (stop the server)*), its log lines and the startup
  warning of a server without credentials. The rest of the server's
  messages and the code comments follow: the repository is going
  English-only.
- The quotes and old messages in Spanish in `CHANGELOG.md` and `CLAUDE.md`,
  in English.

## [1.6.1] - 2026-09-27

### Fixed

- **The Linux launcher called Delphi's `ChDir`, not the POSIX `chdir`.**
  `McpRunJob` sets the working folder of the program it starts, in the
  child process just before `execv`. Plain `chdir` resolves to `System.ChDir`
  (a `string`, and it raises on failure): the path went string - UTF-8 -
  pointer - string - UTF-8 (warning W1057), and a failure would have raised
  an exception in the child. The RTL names the POSIX call `__chdir` (as it
  does `__close`); the launcher now calls it and, if it fails, writes
  `error: no pude entrar en ...` and exits 127, like a failed `execv`.
  Tested live: a remote-run on Zorin starts in its folder.

- **Deploying copied the server and not `node\`.** Not in the product: in
  the release routine. Production kept the desktop node of 2026-09-24 after
  1.6.0 was deployed, so the server kept sending that one to the targets;
  the published zip was right. The deploy now copies what the zip carries
  (the exe and every file of `node\`) and checks each one's sha256.

## [1.6.0] - 2026-09-26

### Added

- **`delphi_move` re-points every relative path that crosses the border of
  what it moves.** Moving the server one level deeper on 2026-09-24 left it
  without compiling: 16 `in '..\vendor'` of the `.dpr`, 16 `DCCReference`,
  an `{$I}` and the search paths, fixed by hand, and the root `.groupproj`
  still pointing at the old place. Now, once the unit and its designer
  file are in place, inside what moved: the units from outside each project
  lists (`.dpr`/`.dpk` and `DCCReference`, through `RenameProjectUnit`, with
  the real old path so a rename works too), the `.dproj`'s search and output
  paths, icon, manifest, `.rc` files, deployed files and imported `.optset`,
  the `.deployproj`, the `{$I}`/`{$R}`/`{$L}` directives - only when the
  file was where the directive says: `{$I jedi.inc}` found through the
  include path is left alone; quoted when the new path has a space; both
  paths of `{$R a.res a.rc}` - and the projects and dependencies of each
  `.groupproj`. Outside it, in everything this session can WRITE (without a
  jail, only the folder above): every directive, listed unit, path and group
  that pointed inside - a sibling project, a unit elsewhere with an `{$I}`
  into it. What points inside travels with it untouched; a copy re-points
  its own. One walker that never crosses a link (a moved junction is not
  walked), one rewriting skeleton for every XML list, entries rewritten one
  by one so the untouched ones stay byte for byte, all under the edit lock;
  what it could not re-point is named, and so is a source folder it skipped
  because it is called like an IDE output (`Debug`, `Win32`). A folder move
  had its own walk for the units of outside projects: now it is this one.
  New battery `test_mudanza` (60 checks; the 1.5.4 binary fails 52 - among
  them, the moved project does not compile).
- **`delphi_config` on a `.groupproj`**: `add-project` / `remove-project`
  write (or take out) what the IDE's *Add existing project* writes - the
  `<Projects>` item, its three targets and its name in Build/Clean/Make;
  idempotent, and a second project with the same name is refused (two
  targets cannot share it). Removing a project takes its name out of the
  `DependsOnTargets` of the projects that depended on it and its path out of
  their `<Dependencies>` (msbuild fails on a target that no longer exists),
  and removes its own targets even when they carry `DependsOnTargets`.
  Adding one goes through ONE path for the aggregates (Build/Clean/Make):
  appended to the list of the one that exists, the missing one created,
  one without the IDE's shape reported, not claimed. `view` lists the
  group's projects and whether they are where it says.
- **`delphi_create` makes a standalone source.** No tool could create a
  `.pas` or a `.inc` that no project lists yet (`delphi_textedit` refuses
  Delphi files, `kind=unit` demanded a project): the unit two programs share
  from `{$IFDEF}` branches of their uses had to be written by hand. Now
  `kind=unit` with no project and an ABSOLUTE `dir` creates it standalone,
  and `kind=include` creates a `.inc` with its content; same gate, same
  writer and encoding as everything the scaffolder makes, never overwriting.
  And a uses clause split in `{$IFDEF}` branches, each ending in its own
  `;` (the desktop node's), was read only up to its first `;`: the units
  view, fix-references and the move saw one branch, and add-unit would have
  written into the wrong one. It is read whole now, and add-unit,
  remove-unit, a rename, adduses and removeuses refuse it with `error:` -
  the writer (`ReplaceUses`) asks too - pointing at `delphi_edit` for the
  branch. `test_mudanza` W1-W4 (the 1.5.4 view lists one branch).
- **`delphi_edit` warns about a brace comment with another brace inside**
  (`{ see {$IFDEF X} here }`): Pascal does not nest braces, the first `}`
  ends the comment and what follows is code - or a real directive. Warned,
  never refused (a lone `{` inside a comment is legal). Four times between
  2026-09-25 and 27 it cost a build round to find.
- **`delphi_config command=fix-references`** (a project or a group): what
  is no longer where it says - moved by hand, outside the tools - is found
  again by its NAME inside the workspace; one match is re-pointed, none or
  several are reported and never guessed; a re-point that did not happen
  is reported, not counted. Search paths that do not exist are reported.
  What lies outside what the session can read is neither looked at nor
  mentioned - not even whether it exists.

### Fixed

- **`delphi_git`'s option filter read the args one way and git another.** The
  gate that refuses git's dangerous options (`--output`, `--no-index`, `-c`,
  `--upload-pack`, ...) split the argument string on spaces, while git.exe
  parses its command line with the Windows C runtime rules: double quotes group
  and vanish, and a backslash is special before a quote. So `--o"utput"=<path>`
  was ONE token the gate did not recognise, and `--output=<path>` to git, which
  wrote a file anywhere on disk - a jail/write escape usable even by a
  read-only client (confirmed with a probe). Now the one tokenizer `TrocearArgs`
  applies the real CRT rules (backslashes included) and the gate judges every
  argument exactly as git will receive it; the executor recomposes the command
  line from that SAME argv with `EnComillas`, its inverse (fixed to double the
  backslashes before a closing quote, which it did not), so git runs precisely
  what the gate approved (clone's URL, in `message`, goes through the composer
  too). `GitRemoteDenied` reads its URLs through the same tokenizer, and
  `EnComillas` lives beside `TrocearArgs` in `Lsp.Guard` so the reader and its
  inverse cannot drift. New battery `test_git_argfilter` (12 checks; the 1.5.4
  binary fails 6 - the disguised options slip through and git runs them) plus
  unit tests for `TrocearArgs` and the round trip that proves `TrocearArgs` and
  `EnComillas` invert each other - empties, quotes and trailing backslashes
  included (a backslash-only argument used to be dropped).
- **A batch of `delphi_edit` swallowed the engine's warnings** (`***`
  mojibake, broken `end.` structure, insertion inside a method...): each
  edit was summarised as "N OK" and the warning was gone. They are appended
  to the batch's answer now, numbered by edit.
- **A directive inside a comment was read as a directive.** Four readers of
  compiler directives - the file directives the move re-points and the build
  gate checks, the conditionals of a split uses clause, the console-test
  detector - ran their own regex over the raw text: a directive commented
  out (with braces, `(* *)` or `//`) or inside a string counted, and the
  `(*$I x.inc*)` form did not. One reader now, `DirectivasPascal`, on the
  lexer the uses reader already had (`CommentLen`/`QuoteLen`). Unit tests
  (`LspTests.Pascal`) and `test_mudanza` R12/W5.
- **`delphi_config` on a `.groupproj` answered as if it were an empty
  project** (no platforms, no configurations, "crossPlatform: yes"), and a
  writing command would have edited the group as a `.dproj`. Anything that
  is not a project is refused too, instead of being read as one.
- **A battery that measured nothing came out green** (0 checks, exit 0).
  `mc.fin` now fails it unless it says why (`sin_checks=`, e.g. no service
  on this machine), and `run_all` fails one that never reached `mc.fin`;
  both read the same mark. `test_docs_static` proves it.
- **A red battery with no FAIL line said nothing** in `run_all`'s summary
  (seen once in a gate: `test_readonly_roots`, 57 PASS and an exit code
  that was not 0; not reproduced in 13 runs). It now prints the exit code
  and the last lines of a battery that failed without saying why.
- **Linux desktop node without a graphical session: 20 s of silence, then
  a D-Bus timeout.** The node now asks ONE detector, shared with the
  launcher (`Mld.Sesion`, in both programs), whether ITS user has a
  graphical session, and answers at once when there is none. The detector
  reads logind's sessions (user, type, state), so the login screen - another
  user's - does not count (GDM keeps `X1024`-`X1027` in `/tmp/.X11-unix`,
  measured on Zorin) and neither does a stale socket; without logind, only
  the sockets of this user; in doubt, it lets the portal try. The launcher
  looked only at `X0`, of anyone, and could disagree with the node; now it
  sets `DISPLAY`/`WAYLAND_DISPLAY` from the same answer, and the server
  gives the node's own reason first (the launcher's "no environment" hid it).
  `/run/user/1000`, hard-coded three times, is now the running user's. The
  node's output lines (`CAPTURA=`, `NO pude capturar:`) live in one include
  read by the node and the server (`NodeProtocolo.inc`).
- **The harness, reviewed**: the `SIN CHECKS` mark is read the way `mc.fin`
  writes it, as a line (`mc.sin_checks_de`; anywhere in the output, a
  reply quoting it would have made an empty battery green); a battery that
  dies before `mc.fin` stops the adb it started (atexit); `test_service_smoke`
  takes only 1060 as "no service here" (access denied came out green) and
  purges the trash copy its write check leaves in a production root.

### Changed

- **One reader of the file directives** (`{$I}`, `{$R}`, `{$L}`):
  `DirectivasDeFichero`, with the position of each path, shared by the build
  jail (`Lsp.BuildRunner`) and the move. A quoted path with spaces is now
  read whole.
- **A path with `&` (a folder `R&D`) broke the `.dproj`, the `.deployproj`
  or the group**: ten places wrote paths into XML attributes by hand,
  unescaped (`DCCReference`, `DeployFile`, `ProfileLibrary`, the group's
  items). One writer now, `XmlAtributo` (`Lsp.Dproj`, next to
  `XmlEscape`/`XmlUnescape`); its reader `AllTagAttr` returns the value
  unescaped, and the readers with their own regex unescape too. The same
  for element TEXT - search and output paths, deploy entries, SDK and
  profile names, the `.profile` and `.sdk` fields, the group's targets;
  about thirty writers composed `<Tag>value</Tag>` by hand: one writer,
  `XmlElemento`, and the readers (`AllTagValues`, `TagValue` - now the
  first `AllTagValues`, case-insensitive like the rest -, `PlatformProperty`)
  return the real value. `XmlUnescape` was not the inverse of `XmlEscape`
  (it turned `&amp;` back first, so `&amp;lt;` came out as `<`), eight call
  sites unescaped on their own (one a value its reader had already
  unescaped, another a registry path that is not XML), six readers of the
  `.sdk` sysroot/library path and the units view read the raw text (a
  Documents folder called "A & B" left a SDK unusable), and a list is now
  cut as WRITTEN (`TrozosEscritos`: the `;` of an entity does not split) so
  only what changes is rewritten. The three private copies of the
  search-path resolver are one helper, `RutasDeBusqueda`. `add-searchpath`
  now accepts `&` (the reason was the XML); a deployed file and its remote
  folder still refuse it - that path to the target is not measured.
  `test_mudanza` X1-X7 and unit tests (the reader is the inverse of the
  writer, entities, the resolver, case).
