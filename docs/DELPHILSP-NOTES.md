# DelphiLSP.exe — field notes (measured, not quoted)

Everything below was verified against **DelphiLSP 37.0.59082.6021** (RAD Studio 13 "Florence") by speaking raw LSP over stdio. Where Embarcadero's documentation is cited it was cross-checked live.

## Announced capabilities (`initialize` response — identical with empty and full client capabilities)

```json
{"textDocumentSync": 1,
 "definitionProvider": true, "declarationProvider": true, "implementationProvider": true,
 "documentSymbolProvider": true, "hoverProvider": true,
 "completionProvider": {"resolveProvider": true, "triggerCharacters": [".", "(", "<", "["]},
 "signatureHelpProvider": {"triggerCharacters": ["(", ",", "<"]},
 "publishDiagnostics": {"tagSupport": {"valueSet": [1, 2]}}}
```

## What actually works

| Operation | Status | Notes |
|---|---|---|
| `definition` / `declaration` / `implementation` | ✅ | Cross-unit verified: call site in unit A resolves to implementation line in unit B; RTL symbols resolve into RAD Studio `source\` tree |
| `hover` | ✅ | Markdown with a `file.pas#line` link + code block (`returnHoverModel: true` switches to a JSON object) |
| `documentSymbol` | ✅ | Full interface/implementation tree. **Works even with no project settings loaded** |
| `completion` (+resolve) | ✅ | Keyword-only without project settings; full symbols with them |
| `signatureHelp` | ✅ | announced |
| `publishDiagnostics` | ✅ | **Only** in `linter`/`controller` mode. Real compiler messages with codes (`E2003`, `W1000`, `H2164`…), exact line:column; severity 1=error 2=warning 3=hint |
| `references` | ❌ | `-32601 Method not found` |
| `workspace/symbol` | ❌ | `-32601 Method not found` |
| `rename` / `codeAction` / `formatting` / `semanticTokens` | ❌ | not announced, not implemented |
| build | ❌ | LSP has no build op; use MSBuild |

## Startup contract

- stdio only; no banner (a manually-launched exe sits silent waiting for framed JSON-RPC).
- `initializationOptions`: `serverType` (`"controller"` | `"agent"` default | `"linter"`), `agentCount` (with controller: 2 = 1 agent + 1 linter — the only Embarcadero-supported topology; the controller **replaces dead/hung children automatically**), `returnDccFlags`, `returnHoverModel`, `storeProjectSettings` (IDE-only), `enableFileWatcher` (default `true`).
- Project settings arrive via `workspace/didChangeConfiguration`:
  `{"settings": {"settingsFile": "file:///C%3A/path/Project.delphilsp.json"}}`

## The `.delphilsp.json` settings file

- Generated by the IDE only when *Generate LSP config* is enabled in Code Insight options **and** settings are re-sent (Reload LSP Server / project reload). Enabling the option alone writes nothing.
- Contains machine-local absolute paths — never commit it.
- **Can be fabricated by hand / by tooling.** A minimal working file:

```json
{"settings": {
  "project": "file:///C%3A/path/MyProject.dpr",
  "dllname": "dcc32370.dll",
  "dccOptions": "--no-config -U\"C:\\...\\lib\\Win32\\release\" -NSWinapi;System.Win;System;Data;...",
  "projectFiles": [],
  "includeDCUsInUsesCompletion": true, "enableKeyWordCompletion": true,
  "browsingPaths": ["file:///C%3A/.../source/rtl/common", "…rtl/sys, rtl/win, VCL, data"]
}}
```

`dllname` selects the compiler front-end (`dcc32370.dll` Win32 / `dcc64370.dll` Win64; suffix `370` = Studio 37.0).

## Behavioral gotchas (measured)

- **`hover` answers on identifier USAGES only.** Hovering the declaring identifier itself, or the
  implementation header, returns `null` (not an error). Hover a call site, a type reference in a
  `var`/parameter declaration, etc.
- In `documentSymbol` results, symbols with `detail: "implementation"` have a `selectionRange`
  that starts at column 0 (the `procedure`/`function` keyword) — useless as a position for
  definition/hover. Symbols with `detail: "declaration"` carry the identifier token itself: use those.

- **Indexing latency**: requests sent while a freshly opened document is being indexed return `-32800 "Request removed"`. Retry with escalating delays; a ~12k-line unit needed ~10–30 s on first open.
- `hover`/`definition` return `null` (not an error) when no project settings are loaded; `documentSymbol` still works.
- Without keeping stdin open the process exits before answering (pipe-close on EOF).
- Positions are 0-based, UTF-16 code units. Content in `didOpen` is UTF-8 JSON — decode legacy CP1252 sources correctly before sending.
- An external DelphiLSP instance coexists fine with the IDE's own instances; each agent holds hundreds of MB on a mid-size project.
- The LSP reads **disk state**; unsaved IDE editor buffers are invisible to it.

## Complete capability inventory (measured on 37.0, 2026-08)

Announced by `initialize` (and verified working): `textDocument/definition`,
`declaration`, `implementation`, `documentSymbol`, `hover`, `completion` +
`completionItem/resolve` (triggers `.` `(` `<` `[`), `signatureHelp`
(triggers `(` `,` `<`), `publishDiagnostics` (with deprecated/unnecessary
tags), `textDocumentSync` = 1 (full), `workspace/didChangeConfiguration`.

**Present as strings in the binary but DEAD over stdio** — measured
`-32601 Method not found` in `agent` and `controller` modes, with and
without `enableLsif`: `textDocument/references`, `typeDefinition`,
`foldingRange`, `documentLink`, `textDocument/diagnostic` (pull model).
These appear to be IDE-internal code paths (the IDE's Find References does
not go through the public LSP surface). Do not trust the binary strings:
probe.

Not present at all: `rename`, `codeAction`, `formatting`,
`workspace/symbol`, `semanticTokens`, `callHierarchy`, `inlayHint`.

`initializationOptions` (binary-verified set): `serverType`
(agent/linter/controller), `agentCount`, `returnDccFlags`,
`returnHoverModel`, `storeProjectSettings`, `enableFileWatcher`, and
**`enableLsif`** (Florence-era, undocumented as an option; the documented
counterpart is the registry switch below).

Navigation semantics (measured on 37.0):

- `definition` = the **body** in the implementation section.
- `declaration` = the **interface declaration**.
- `implementation` answers **like declaration** (redundant in this engine).
- For **global routines**, `declaration` also returns the interface entry
  and only `definition` reaches the body — the decl/def pair is how you
  jump between the two halves for globals and methods alike.

Troubleshooting facts (docwiki "Troubleshooting: Delphi LSP"):

- definition/Ctrl+Click requires symbol reference info (`$Y`) on, and the
  declaring source reachable via search/browsing path when DCUs shadow it.
- DelphiLSP only works inside **active** IFDEF branches.
- Files need **consistent line endings** (mixed EOLs break it).
- Server-side logging: registry `HKCU\Software\Embarcadero\BDS\<ver>\LSP`,
  DWORD `DelphiLSPLog` = 255 → logs in `%LOCALAPPDATA%\Temp\DelphiLSP`
  (log files may include source code).

## LSIF (measured)

- The compiler generates the indexes: `dcc32 --lsif` / `dcc64 --lsif`
  ("output LSIF files", listed in `dcc32 --help` on 13.x).
- RAD Studio 13.1 ships pre-generated indexes for the core libraries:
  `lib\win32\release` (114 files) / `lib\win64\release` (118) /
  `lib\*\debug` — one `.lsif` per package (rtl.lsif, vcl.lsif...).
- The files are **standard LSIF**: JSON Lines with `vertex`/`edge` records
  per the Microsoft LSIF spec (`{"id":1,"type":"vertex","label":"document",
  ...}`), `languageId: "Delphi"`.
- `enableLsif: true` in `initializationOptions` changes NOTHING in the
  announced capabilities and does not wake the dead methods; it appears to
  accelerate definition/hover internally.
- Docwiki ("Delphi LSIF"): LSIF is used only when BOTH the referenced
  package and the navigating file have LSIF; otherwise silent fallback to
  the compiler. Generation = Linking option "Output .lsif file" (the
  `--lsif` switch). Global kill-switch: registry
  `HKCU\Software\Embarcadero\BDS\<ver>\LSP`, REG_SZ `EnableLsif` = false.
  Third-party libraries can generate their own LSIF from source.
- **Measured content of the shipped indexes**: rtl.lsif (321 MB), vcl.lsif
  (108 MB) etc. contain `document`/`range`/`resultSet`/`definitionResult`/
  `hoverResult`/`moniker` — and **zero `referenceResult`**. They serve
  definition + hover + symbolic identity, not find-references.
- **BUT references can be computed by inverting the graph.** A
  project-level index generated with `dcc64 --lsif <dpr>` (plus the
  project's usual options) records a `range` for identifier USAGES too,
  each linked `range -next-> resultSet -textDocument/definition->
  definitionResult -item-> [definition ranges]`. Grouping usage ranges by
  their definition range IS find-references — compiler-exact, homonym-free.
  Measured on a real 34-unit project: 3.9 MB index generated in 0.5 s of
  compilation; graph load 0.08 s; a symbol used from 6 different units
  returned all 13 usages instantly and correctly.
- **Monikers give cross-package identity**: usages of external symbols
  carry `{"kind":"import","scheme":"Delphi","identifier":
  "*/System.SysUtils.Exception"}`; a package's own symbols get export
  monikers (`MyProj/MyUnit.MyFunc`). Joining indexes by moniker identifier
  links references across projects and into the RTL.
- Caveats: the index reflects the last successful compilation (stale after
  edits until rebuilt), and only covers units the compiler actually
  compiled.
