# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/) and the project adheres to
[Semantic Versioning](https://semver.org/): MAJOR.MINOR.PATCH, where MINOR
adds tools/capabilities and PATCH fixes. The server reports its version in
the MCP `initialize` response (`serverInfo.version`).

## [Unreleased]

## [1.27.0] - 2026-11-05

A minor version about what the server starts and how long a client waits. Every
run in a Windows container - the form renderers, the style converter, `brcc32`,
`delphi_test` - takes one of a fixed set of slots, so a long session keeps
starting them (Windows keeps an entry for every container name until the user
logs off, and stopped creating processes); what the server starts no longer
inherits its configuration, and a program it takes from a written path is judged
where it lives. The IDE's form reader judges an edit, a write or a `lint` only
within the minute a client waits (`DSGN-185`, `DSGN-188`, `EDIT-131`). `layout`
judges what the renderer measured, an FMX form by the VCL's judge; the form
renderers carry the manifest the IDE gives an application, so native FMX
controls are drawn, and bring a form's whole ancestor chain from other folders.
A deploy says what another configuration ships (`BUILD-068`), a `Clean` what it
cleaned (`BUILD-069`), and a styles folder takes one `.rc` (`STYLE-067`). No
setting needs to change; deploy the server with its two form renderers (they
speak protocol 5). Validated before the release through Hermes on a second
machine by Qwen3.8 Flash Next (a full test of every tool and directed tests of
what changed, three rounds) and GPT-5.6 Luna (a full test and directed tests).

### Fixed

- `delphi_desktop` on Linux reads a window's title as the application sets it: `_NET_WM_NAME`, in UTF-8, and only without it the old `WM_NAME`, as Latin-1. It read only `WM_NAME`, and as UTF-8: an accented title came out with a `?` in `windows` (measured on KDE Plasma: "Pasarela de grabaci?n de Wayland a X"), and `screenshot window=` with an accented piece of a title did not find its window.
- The form renderer, the style converter, `brcc32` and `delphi_test` no longer stop starting after a long session. Each run registered its Windows container under a new name, and Windows keeps one entry per distinct container for the whole logon session and never gives it back: after eight days of test runs no process could be started in a container in that session - a bare `cmd` neither, measured (`CreateProcess` 1450) -, so every `preview`, `layout`, edit judged by the IDE's reader and `delphi_test` failed until the user logged off. A run now takes the first free slot of its server, whose name - and so its entry - is the same every time, with a new profile registered for that run and deleted with its answer. Two runs at the same time still get different slots, also when one is the Windows service and the other a console instance of the same server; a slot whose folder or profile could not be removed is not used again until they can be, so a test that leaves something behind does not hand it to the next one; and with every slot taken a run gets a container of its own instead of failing.
- A drive path glued to a command-line option comes out with its virtual unit. The compiler line of a `delphi_build` with `verbosity=verbose` carried `-LEC:\...`, `-LNC:\...`, `-NBC:\...` and `-NHC:\...` with the real drive letter: a drive only started after something that was not a letter or a digit, and an option's name is letters. A network path glued to an option was already masked (`-U\\host\lib`); that rule now says where a path starts for drive letters and for the server's own folders too, which glued to an option would have come out with the Windows user in their path.
- `delphi_config add-searchpath` names every folder a path with `$(Config)` or `$(Platform)` stands for when none of them exists (`CFG-147`): `lib\$(Config)` with no folder named only `lib\Debug`, while `lib\Release` would have done as well. A macro it does not resolve gets `CFG-148`, which says that it resolves the IDE's and msbuild's macros and the properties the project defines itself, not the environment of the server, and that `set-property` writes such a value as it is for the build to judge; `CFG-017` said "unknown macro" of `$(APPDATA)`, which the IDE accepts.
- **Security.** What the server starts no longer inherits its configuration from the environment. `paclient`, `adb` and its daemon, `reg.exe` and the DelphiLSP engine got the server's whole environment, so a server configured through it - the console mode, with `DELPHI_MCP_TOKEN` or `DELPHI_MCP_READONLY_TOKEN` - handed its token to each of them; `msbuild`, `git` and everything in a container already got it without the `DELPHI_MCP_*` variables. Every launch now asks one rule. The Windows service, configured through `settings.ini`, had nothing there to hand.
- `delphi_paserver remote-run` no longer refuses an argument with `;`, `|`, `&`, `` ` ``, `$`, `<` or `>` (`SYS-003`): there is no shell anywhere on the way - the arguments go from the job file to the program's own argument list, `execv` on Linux and `CreateProcess` of a native binary on Windows - and the program is the one the project deployed, so they arrive as written. An argument with a line break or a NUL character is refused (`RUN-026`), since each one travels to the target on a line of its own; it was turned into a space without a word. The same holds for the name in `exe` (`PAS-006`). On a Windows target the launcher checks each argument again before it composes the program's command line (`JOB-012`).
- What the server hands a Delphi program of its own - the form renderer, `paclient`'s password, the filter of `delphi_test` - is judged by one rule: what `ParamStr` receives whole, with no control characters. The filter only looked for a double quote, and now refuses a control character too (`TEST-037`); the renderer's `--dropped` value was the one it did not judge.
- A file fetched from a target by the name a program printed (`CAPTURA=`) is refused when the name carries what splits a `paclient` field, a `,` or a `;` (`FETCH-001`): `paclient` reads `--get=<file>,<destination>` up to the first comma, and the rest would have been taken for the local destination.
- The IDE's SDK folder is one answer. When the operator redefined `BDSPLATFORMSDKSDIR` in the IDE with a variable its table does not resolve (`$(USERPROFILE)\SDKs`), a build's table kept that text while the server read and wrote SDKs in the folder of the registered ones. Both now take the second, from one reader; what the IDE itself does with such a value is not measured. Reading the SDK folder from the table put the server in a loop with no end until its stack gave out - judging a place of the IDE asked for the SDK folder, whose table reads `rsvars.bat` through that same judge -, and the judge now asks for the installation first. Read in the code and not reproduced: the previous version entered that loop with a redefinition holding a macro.
- A `delphi_build target=Deploy` to a PAServer says what the project deploys on that platform with another configuration and this one does not (`deployNotThisConfig`, `BUILD-068`). `delphi_config add-deployfile` adds a file to one configuration - the active one when `config` is not given -, as the IDE's Deployment Manager does, and a deploy of another configuration went without it and without a word: measured against a Linux target, a data file added for Debug and an FMX app deployed in Release that started without it. `add-deployfile` now says the file is for that configuration only.
- The manifest generated for a Linux deploy no longer says that a GUI app needs a richer one (`BUILD-067`): for Linux64 the IDE's Deployment Manager writes the same thing, the project output, and an FMX app deployed with it runs on the target (measured). What else an app needs there goes in with `add-deployfile`.
- **Security.** A knowledge vault reached through a link is no longer copied or listed. The read gate already refused a vault note by its real path, but the tree copier (`delphi_move copy=true`, the staging folder of `delphi_test`) and the file walker (`delphi_list`) follow a link whose target can be read, and behind it they only recognised the vault by the text of the path: a link in a root to a reference folder that holds a vault copied its notes into the workspace, where any tool read them. One rule now says what is in a vault, by its text or its real path, for the gate and for both walkers. It predates this version.
- `delphi_changeset` moves a file by the same rule as `delphi_move`: both sides writable, no protected place, and the same real volume - asked when the move is staged and again when it is applied. It only judged the destination, and moved across volumes by copying and deleting, which `delphi_move` refuses (measured: a staged move from one drive to another was committed). It now renames, and never copies.
- `delphi_move`, `delphi_delete`, a merge into an existing folder and the undo of each one move a file only by renaming it, and fail instead of copying. They renamed with a call that, for a file on another volume, copies it and deletes the original (measured): a guard already refuses two drive letters, and a volume mounted inside a root shares the letter. Moving a folder already refused another volume.
- A deploy of a configuration whose project output the manifest does not list ships the binary. The manifest was completed only when the platform had no project output at all, so a project deployed first in one configuration and then in another one it does not declare - or one declared after the manifest was written - deployed nothing, and the build answered success (measured). Each missing configuration gets its entry, and `BUILD-014` says so.
- A deployment entry whose own `Condition` cannot be read is no longer taken as one for every configuration: `remove-deployfile` with `config` leaves it, and the deploy note does not count it. On a target other than Windows, two deployed names that differ only in case are two files.
- **Security.** A program the server takes from a written path - the `adb` an Android `.sdk` names, `paclient`, and the DelphiLSP engine and `brcc32` of the installation - is not run from a folder this session can write: it would run as the server. `git` and `msbuild`, found by name, were already judged that way; `adb` only had to exist (measured: an `adb.exe` built inside a root ran). The refusal says why (`ADB-035`, `RUN-027`, `LSP-053`, `STYLE-068`) instead of claiming there is no SDK or no `paclient`; `brcc32` also runs in its container, so for it this is a second barrier.
- **Security.** What `delphi_test` copies next to the test executable for its sandbox is only what the session can read: git metadata beside an executable built into a repository's root reached the sandbox, where the agent's test code read it (measured), although every tool refuses them.
- `delphi_styles build` compiles its resource script under a fixed name: the name of the agent's `.rc` reached `brcc32`'s command line, where one starting with `-` would have been an option.
- `delphi_package` judges the folder it packs with the read gate - it only reads it; the zip is judged where it is written. A reference folder could not be packed into the workspace (measured).
- `delphi_paserver add-profile` hands `paclient` the port as the number its gate judged, and `test-connection` with `host` dials and reports that number: `$FBB3` or `0xFBB3` passed the gate and travelled, or was answered, as typed.
- Descriptions that promised more than the code does: `delphi_config` says that `add-deployfile` is for one platform and configuration and that `add-searchpath` takes one platform or all; `delphi_designer lint` leaves to `set` a property a class of the project publishes; `preview` runs none of the project's code (the IDE's design packages do run), and a read-only credential has it without `out=` or `state=`; `remote-run`'s arguments arrive as Delphi's `ParamStr` reads them on a Windows target.
- `delphi_designer layout` of a VCL form with a frame inline names each box by its path (`Frame11.Edit1`), as `set` and `get` take it. Boxes were matched by the bare name, so a control of the frame and one of the form with the same name took each other's coordinates (measured).
- When the operator redefines in the IDE a variable the server also sets for a build (`TEMP`, `TMP`), the build gets one value: two different values of a name both reached `msbuild`'s environment, while the server's own reader of it kept the last one.
- An edit of `delphi_designer` stops judging when a client stops waiting. Each judgment by the IDE's form reader got the time of a `preview`: one that hung answered `DSGN-185` after 75 s, when the client had given up at the minute (measured), and - read in the code - a second judgment of the same edit got its own 75 s. The judge's own watchdog now fires when the edit's time is up, the server stops a judge that does not even answer to it a margin later, and none is started when no time is left.
- `delphi_edit insert=rutina-global visible=true` finds the `implementation` of the unit by the rule `adduses` uses: the word, wherever it is on its line. With `implementation uses X;` on one line it found none and undid the body (`EDIT-109`, measured); what a line carries before the word stays in the interface, ahead of the declaration.
- `delphi_designer preview` of a form whose ancestors live in other folders of the project brings the whole chain at once: of each form it brings, the form of its ancestor, read from its unit. It brought one link per run of the renderer, three at most, so a chain of four in other folders came out half drawn - measured on the samples the IDE installs. The renderer still judges what it is given, and another run is only for what it alone finds, such as a frame of a form brought in; the call's time limit bounds them.
- `delphi_styles build` with more than one `.rc` in the styles folder refuses and names them (`STYLE-067`), and `lint` says the same: it compiled the first one Windows listed without a word, while `lint` judged them all. One manifest per styles folder, as before.
- The server's own temporary folder reaches a message as the server's folder, `<server>`, and its name never: the renderer's failures named it `(server)`, and the output filter `<server>\__delphi-temp\...`. One composer for both.
- `delphi_completion` keeps its notes on the position and the trigger when the engine answers without a list (a `null` or an error): they were about the question and went only with an answer that had items.
- `delphi_config get-property` and the other readers of a project property for a build (the output path, the SDK, the PAServer profile, the packages, the engine's settings) give the value msbuild fixes where the property is defined: a reference to another property is its value at that point, empty when that one is defined further down. `<X>a</X><P>$(X)</P><X>b</X>` read `P` as the raw `$(X)` where msbuild fixes `a`, because the reader re-expanded the raw text with an expander of its own instead of the value the build gate already computes for each element; it now returns the gate's value, the same judge, with an unknown macro left as `$(X)` for whoever has its table (measured with the msbuild oracle: a reference before the definition is empty, after it the value).
- `delphi_config add-searchpath` resolves a property the `.dproj` defines itself, the way the build does. `set-property MiLib=libs` and then `add-searchpath $(MiLib)\comun` was refused as an unknown macro (`CFG-148`) while `delphi_build` resolved `$(MiLib)` and compiled - add-searchpath expanded only the IDE's and msbuild's macros, not what the project defines. It now composes the `.dproj` in memory as `add-searchpath` will write the path - into the group's existing `DCC_UnitSearchPath` if there is one (where the build reads it), at the end of the group if not; one shared function places it for the writer and the probe - and reads that value back with the build's own judge (`VeredictosDeElementos`), so a `$(X)` resolves to what msbuild fixes at that point (empty when `X` is only defined further down, not its final value), a project property beats an environment variable but not a reserved macro, in one pass per build; a macro nobody defines and the server's own environment stay refused (`CFG-148`), and the build gate still judges what it reads.
- `delphi_designer preview` draws a form with native FMX controls (`ControlType = Platform`: a `TEdit` or a `TMemo`, as in the IDE's Controls sample). The renderers had no manifest, and such a control raised "This control requires version 4.70 or greater of COMCTL32.DLL" (`DSGN-061`, the same outside the container: measured). They now carry the one the IDE gives an application (`default_app.manifest`: the dependency on Common Controls 6 that `bds.exe` itself has, and no DPI awareness, so what they measure keeps its scale); the style converter already had its own. VCL previews are drawn with the Windows theme, as the IDE's designer shows them. The copy each container runs keeps that manifest: the COM classes the container cannot find go inside it, where they replaced it.
- A failed `delphi_git clone` no longer leaves its empty folder behind now and then. Removing the folder the call created bounced with a sharing violation - something holds a new folder open for an instant - and it stayed: between 1 and 10 failed clones in 40, each one removable a second later (measured). It is now retried by the policy a rename already used for the same reason, and what still cannot be removed is logged with Windows' error.
- `delphi_build target=Clean` says what it cleaned and what it did not (`BUILD-069`, `cleanNote`): what msbuild builds for that platform and configuration into the project's declared output folders. What another configuration built, or an output folder the project no longer declares - the one before a `set-output` - stays, and an agent found that out with `delphi_list`.
- Refusals that say exactly what they refer to: `TEST-037` names the character the test runner cannot receive (`U+0009`, a tab), and so do `PAS-019` (a `paclient` password, without repeating it), `DSGN-065` (a value for the form renderer) and `RUN-025` (an argument of `remote-run` on a Windows target, or that it is empty); `RENAME-019` says that a form binds by name a component, an event and the form itself (renaming a form's global variable was told it was "a published member"), and that the form's own name is changed in the IDE; `STYLE-008` says that a text `.style` can be written with `delphi_textedit` (`object TStyleContainer` with one object per style), not only exported from the Bitmap Style Designer.
- The server's places of the IDE follow a change of the SDK folder while it runs, as the library zone already did: the folder was read once per process, so a redefinition in the IDE's Environment Variables, or the SDK Manager's own entries, reached the read and write gates only after a restart.
- The platform default style the designer and `delphi_styles lint` judge `StyleLookup` against is cached per style converter. It is produced by the converter, and one cache named `win10-default.style` served every converter the machine ever had; a new one now makes a new cache, and the old ones are removed.
- The form renderers read a class's ancestor and a unit's `uses` with the server's own declaration reader (`Lsp.PascalDecl`, the one check-binding uses) instead of regular expressions of their own.
- `delphi_designer layout` of a VCL form judges what the VCL measured when the form renderer answers (`boxesFrom=renderer`): a side of zero, a control outside its parent, a band with no room, two siblings that overlap, and the form's client area. The boxes already came from the renderer, but the judgments still came from the text's own arithmetic: a `TLabel` whose caption made it wider than the `Width` its `.dfm` wrote covered a `TEdit` in the boxes of the same answer, and the answer said `clean` (measured); a size the `.dfm` does not write was called unknown next to the box that measured it. Without the renderer the text's arithmetic judges, as before.
- `delphi_designer layout` of an FMX form is judged by the same rules as a VCL form, by one judge: a warning's coordinates are relative to the container it names, as its text says (`... and "Panel1" is only 100 x 100`) - FMX gave them in form coordinates (measured: `from (130,70)` for a control at 80,10 of its panel) -, and the children of a container that places them itself (a `TFlowLayout`, a `TGridPanelLayout`, the tabs of a `TTabControl`) are no longer reported outside it.
- What `delphi_edit`, `delphi_changeset` and `delphi_upload` report about a form they wrote, and `delphi_designer lint`, give the IDE's form reader only what is left of the time a client waits, counted from the start of the call: each reader got the time of a `preview`, so with the write already on disk the answer could come after 75 s (measured with the reader hung), past the minute a client waits, and a client that gave up and retried could apply the edit twice. When the reader could not be asked or did not answer, a write now says so (`EDIT-131`), as `lint` does with `DSGN-154`: it said nothing, and the silence read as "the form loads".
- `delphi_paserver remote-run` judges `exe` by the target's own rule: on a target other than Windows `exe=tool` is not the `Tool` the project deploys (`PAS-063`). It compared without case everywhere, so on Linux a file the project does not deploy ran.
- `delphi_symbols` of a folder reads each unit's interface by the section rule `adduses` uses: with `implementation uses X;` on one line it listed the implementation's routines as the unit's interface, and with `unit X; interface` on one line it listed nothing.
- A change to an IDE registry key that did not exist when the server started (the first `BDSPLATFORMSDKSDIR` override, the first platform SDK, the Editor or Library keys), or that was deleted and created again, is picked up without restarting the server: the watch on such a key was never set.
- A file's fingerprint is its UTC write time as the file system keeps it: a change of the machine's time zone no longer renames the default-style cache and the render package box. Both are rebuilt once after upgrading.
- `delphi_designer lint` and the warnings of a form write (`EDIT-127`, `EDIT-131`) say why the IDE's form reader was asked: for a form whose only part no table judges is an inline frame, `lint` said "0 line(s) hold a property the class stores by code" (measured), and a write said it was asked about a property. With lines the tables cannot judge, the text is the same as before.
- `delphi_designer layout` of an FMX form, and the check after an `insert` or a `set parent=`, no longer say that the part of a control outside its container "is not visible": that is the VCL's rule. FMX draws it over what is around unless a container clips its children (`ClipChildren`), and `preview` showed the button whole while the warning said otherwise (found by Hermes' directed test of 1.27). A VCL warning keeps its text.
- Upgrading: the form renderers speak protocol 5 (their switches are composed and read from one file, `FormRenderProtocolo.inc`). A renderer of an earlier version left next to this server says so (`DSGN-184`) instead of being misread: deploy the server and both renderers together, as the release zip ships them.
