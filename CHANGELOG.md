# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/) and the project adheres to
[Semantic Versioning](https://semver.org/): MAJOR.MINOR.PATCH, where MINOR
adds tools/capabilities and PATCH fixes. The server reports its version in
the MCP `initialize` response (`serverInfo.version`).

## [Unreleased]

### Fixed

- A drive path glued to a command-line option comes out with its virtual unit. The compiler line of a `delphi_build` with `verbosity=verbose` carried `-LEC:\...`, `-LNC:\...`, `-NBC:\...` and `-NHC:\...` with the real drive letter: a drive only started after something that was not a letter or a digit, and an option's name is letters. A network path glued to an option was already masked (`-U\\host\lib`); that rule now says where a path starts for drive letters and for the server's own folders too, which glued to an option would have come out with the Windows user in their path.
- `delphi_config add-searchpath` names every folder a path with `$(Config)` or `$(Platform)` stands for when none of them exists (`CFG-147`): `lib\$(Config)` with no folder named only `lib\Debug`, while `lib\Release` would have done as well. A macro it does not resolve gets `CFG-148`, which says that it resolves the project's and the IDE's macros, not the environment of the server, and that `set-property` writes such a value as it is for the build to judge; `CFG-017` said "unknown macro" of `$(APPDATA)`, which the IDE accepts.
- **Security.** What the server starts no longer inherits its configuration from the environment. `paclient`, `adb` and its daemon, `reg.exe` and the DelphiLSP engine got the server's whole environment, so a server configured through it - the console mode, with `DELPHI_MCP_TOKEN` or `DELPHI_MCP_READONLY_TOKEN` - handed its token to each of them; `msbuild`, `git` and everything in a container already got it without the `DELPHI_MCP_*` variables. Every launch now asks one rule. The Windows service, configured through `settings.ini`, had nothing there to hand.
- `delphi_paserver remote-run` no longer refuses an argument with `;`, `|`, `&`, `` ` ``, `$`, `<` or `>` (`SYS-003`): there is no shell anywhere on the way - the arguments go from the job file to the program's own argument list, `execv` on Linux and `CreateProcess` of a native binary on Windows - and the program is the one the project deployed, so they arrive as written. An argument with a line break or a NUL character is refused (`RUN-026`), since each one travels to the target on a line of its own; it was turned into a space without a word. The same holds for the name in `exe` (`PAS-006`). On a Windows target the launcher checks each argument again before it composes the program's command line (`JOB-012`).
- What the server hands a Delphi program of its own - the form renderer, `paclient`'s password, the filter of `delphi_test` - is judged by one rule: what `ParamStr` receives whole, with no control characters. The filter only looked for a double quote, and now refuses a control character too (`TEST-037`); the renderer's `--dropped` value was the one it did not judge.
- A file fetched from a target by the name a program printed (`CAPTURA=`) is refused when the name carries what splits a `paclient` field, a `,` or a `;` (`FETCH-001`): `paclient` reads `--get=<file>,<destination>` up to the first comma, and the rest would have been taken for the local destination.

## [1.26.1] - 2026-11-03

A patch for what measuring the build after 1.26.0 found. A project can no longer have the
build read the IDE's per-user data folder, where the PAServer connection profiles keep their
password: what a build reads because the project says so is judged by one rule, inside the
workspace or the IDE's library. The build gets the variables the IDE gives its own build, so
a search path through `$(BDSLIB)` or a catalog compiles as in the IDE, and `add-searchpath`
takes `$(Config)`. `set-version` refuses what it cannot rewrite instead of answering that it
did, a Linux binary no longer carries the service's temporary folder, and a variable that
`rsvars.bat` empties stays empty. No setting needs to change. Validated before the release
through Hermes on a second machine by Qwen3.8 Flash Next (directed tests of what changed).

### Fixed

- A Linux binary that `delphi_build` or `delphi_test` compiles no longer carries the server's temporary folder, with the Windows user of the service in its path: the Linux linker records the path of its temporary file in the ELF, and msbuild got the service's `%TEMP%`. Each build now gets a temporary folder of its own inside its `.dcu` folder, removed when it ends, and the build gate reads a `$(TEMP)` of the project as that same folder. The compiler makes even a relative `TEMP` absolute (measured), so what the ELF records is a path of the project.
- `delphi_build` reads a variable that RAD Studio's `rsvars.bat` sets empty (`FrameworkSDKDir`, `PlatformSDK`) as empty, as msbuild does: the build gate's table dropped an empty one and took the value of the server's environment instead. With the service's environment defining it, a search path through it was judged inside the roots while the compiler read it from the root of the project's drive.
- `delphi_config set-version` refuses, with nothing written, a project whose `FileVersion` key - the one the build takes the binary's version from - is written in a form it does not rewrite in place: inside a CDATA section or a comment, or with an XML entity in its name (`CFG-146`). It wrote the numbers, left that key as it was and answered that the keys said the new version, while the binary came out with the old one; with no numbers it said there was no version information at all (`CFG-003`). It reads back every build the project compiles, every platform by every configuration, not only the default one.
- `delphi_build` gives msbuild the variables the IDE gives its own build - `$(BDSLIB)`, `$(BDSBIN)`, `$(BDSUSERDIR)`, the catalog repositories, `$(BDSPLATFORMSDKSDIR)` and the operator's overrides from Tools > Options > Environment Variables - so a search path written with them compiles as in the IDE (measured in the IDE: the project's body sees all of them, with the values the server already used for the library zone). `delphi_config add-searchpath` accepted `$(BDSLIB)\$(Platform)\release` and the build then refused it (`BUILD-050`): msbuild only had `rsvars.bat` and read the macro empty. The build, its gate and `add-searchpath` now read one table.
- `delphi_config add-searchpath` resolves `$(Config)`, and `$(Platform)` without `platform=`, for every build the path applies to: every configuration the project compiles, and every platform it compiles when no platform is given. The jail holds for each of them and one of their folders has to exist. `lib\$(Config)` was refused as an unknown macro (`CFG-017`) even with `lib\Debug` there - the `..\lib\$(Platform)\$(Config)` the IDE writes for a component's `.dcu` files could not be added.
- **Security.** `delphi_build` no longer lets a project read the IDE's per-user data folder, its SDK folder or a registered sysroot. The build gate judged the paths of a project's values with the places of the code-insight engine, which include those of the IDE, so a search path to `$(APPDATA)\Embarcadero\BDS\<version>` - where the PAServer connection profiles live, with their password - passed, and an `{$I}` with a bare name then had the compiler read a file there and quote it in its errors, while `delphi_read` refused that same file (measured on a decoy profile). What a build reads - the project's values, its `{$I}`/`{$R}` directives, the units its main source names with `in`, the links in its tree, the files the `.rc` of an `RcCompile` names - is now judged by one rule: inside the workspace or the IDE's library (its installation, its catalogs and its Library Path), library zone on or off (`BUILD-050`, `BUILD-028`, `BUILD-052`, `BUILD-061`, `BUILD-063`). No project on this machine was affected: none of 7,981 `.dproj` and `.optset` files points to those folders.

## [1.26.0] - 2026-11-03

A minor version about reading things as the tools the server stands in for
read them. The form designer says in which file and on which line a property
or a control lives when it comes from an inline frame or an ancestor, and
`layout` knows what a container does with its children by its class's
ancestry, not by a list of names. The build gate reads a project as msbuild
does - an `<Import>` path unescaped, a `$( Name )` as written, the IDE's macros
empty in the body where msbuild has not defined them yet, a device path
refused - and each of those had been a way to compile from outside the roots.
A program run on a Windows target and a `delphi_test` filter get their
arguments as a Delphi program reads them, names are compared as NTFS compares
them instead of by the user's locale, and the style converter runs in a
container of its own, as the form renderers do. `delphi_config view` shows the
version a build puts in the binary. No setting needs to change. Validated
before the release through Hermes on a second machine by Qwen3.8 Flash Next (a
full test of every tool and directed tests of what changed).

### Fixed

- `delphi_delete purge` does not let one agent purge a file named like an owner marker (`*.by`) inside the copy another agent sent to the trash: it was taken for an orphan marker, and nobody asked whose copy held it. Such a file arrives by git, a copy or a zip; the trash's owner rule now covers it.
- `delphi_changeset` does not create a project file (`.dproj`, `.groupproj`), as `EDIT-128` already said and `delphi_textedit` already did: it refused only to edit one, and a `create` was staged, previewed clean and written. It can still move or delete one, as `delphi_move` and `delphi_delete` do.
- `delphi_build target=Deploy` that fails no longer tells you to kill a remote-run job that does not exist. `deployLockedNote` looked for `E0017` and the watcher's name anywhere in msbuild's console, so a folder with such a name was enough; it now reads the lines msbuild classifies as errors, with both on the same line.
- `RENDER-026` says which file holds the inline it left out: the form you asked for may not be the one that closes the cycle.
- What lives in another file of a form now says which file, and its line there. A property the IDE's reader skipped inside an inline frame's or an ancestor's file came out of `delphi_designer preview` without a line while `DSGN-114` promised "line says where each one is", `lint` gave no line, and a frame that could not be read named only the form. A control inside an inline frame that the form does not override came out of `layout` with `line: 0`, in its box and in its warnings. Now `ignored` entries, `lint` warnings and `layout` boxes carry `file` and the line in it, and `layout`'s warnings say `line N of <file>`. The renderer says which file it was reading, and where each control is written (render protocol 4). A frame that contains itself no longer counts as a property in `DSGN-114`: `RENDER-026` already names its file and what to do.
- `delphi_config view` shows the project's version (`version`, the one its default build puts in the binary, read as msbuild reads the `.dproj`), whether that binary carries it (`versionIncluded`), when the VERSIONINFO numbers and the FileVersion key disagree, both (`versionMismatch`), and the other versions the `.dproj` writes for other platforms or configurations (`versionElsewhere`). The first value written in the file is not always the one the build uses: in 102 of 2,739 real projects it was not. After `set-version` there was no way to read it back but to open the `.dproj`.
- `delphi_changeset` creates a file that is not Pascal as `delphi_textedit` does: in CRLF, without a final line break nobody wrote. A `.json` or a `.txt` came out with one; a source or a form still ends in its line break, as `delphi_create` writes it.
- `delphi_designer insert` and `set parent=` on an FMX form say when the control sticks out of its parent (`outsideParent`), as they did on a VCL form. FMX was skipped for a reason that no longer held: `layout` measures FMX forms since 1.24. The renderer gets the 45 s of `layout` on a VCL form, not the 75 of a preview: the control is already written, and a client that gave up first would insert it again.
- A remote job is finished only when the launcher's closing line is the last one of its output, whole. A program that printed the sentinel inside a line, or an output read while the launcher was still writing it, was taken for a finished job.
- A network path with an accented letter, inside the JSON of an answer, comes back in its declared form. The JSON escapes a letter that is not ASCII, and the matching wrote it as it was, so the server's real host name showed.
- A program run on a Windows target (`remote-run`, and the desktop node) gets its arguments as Delphi reads them. The launcher composed the line by the rules of the C runtime, so a Delphi program got a final backslash doubled and a double quote turned into backslashes: `delphi_desktop type` with `di "hola"` typed `di \hola\`. The text of `type` now travels encoded and the node decodes it; an argument with a double quote, or an empty one, for a program on a Windows target is refused before anything runs (`RUN-025`), since Delphi's `ParamStr` cannot receive the first and skips the second, moving the ones after it up one (`a "" b` reached the program as `a b`).
- Two `delphi_adb screenshot` calls on the same device at once each get their own capture. The capture on the device had one fixed name and no lock, so one call took the other's image and the other found none; each now names its own, and removes it from the device whatever happens: `screencap` opens its file before it captures, and one that failed left that empty file there with its unique name.
- `delphi_build` refuses a path the build reads that carries a device prefix with no drive or network path behind it (`\\?\GLOBALROOT\Device\...`, a volume by its GUID): `BUILD-050`, outside every root. The gate dropped the prefix and judged what was left, a relative path that fell inside the project, while the compiler opens the device.
- `delphi_build` no longer reads a `$( Name )` with blanks inside as `$(Name)`: msbuild does not trim the name (measured: a group under `'$( Config )'==''` applies with Config=Release). The reader of a group's `Condition` trimmed it, took that group as not applying, and the gate did not judge the search path it set: the build compiled a unit from outside every root. Every reading of a `$(...)` now takes the name as written; one with blanks is a name the gate cannot evaluate, so what depends on it is judged either way or refused.
- `delphi_build` reads the path of an `<Import>` as msbuild does, after unescaping it (`%2E%2E` is `..`, measured). The gate judged the written text: an import that began like one of the IDE's and climbed out with `%2E%2E` was trusted without being read, and one under an `Exists` of itself was skipped as missing while msbuild imported it. In both, msbuild loaded a file the scan never saw, and ran what it asked for.
- `delphi_build` judges a value of the project's body with the macros msbuild has there. `$(BDSLIB)`, `$(BDSBIN)`, `$(BDSUSERDIR)`, the catalog repositories and `$(BDSPLATFORMSDKSDIR)` are defined by the targets imported at the end, and in the body they are empty (measured). The gate filled them from the IDE's table and judged a folder of the IDE, while the compiler got the rest of the path hung from the project's drive: a search path read units from outside every root. No project of a census of 3,486 uses them where msbuild reads them.
- A search path that names one folder twice, differing only in case or in a final backslash, reaches the language server once, as the IDE's library already did; two folders that differ only in `ss` and `ß` stay two, as they are on disk.
- A folder whose name holds a `$(...)` is read as msbuild reads it. The server expanded a macro again inside the value of another, so a project in a folder `a$(Config)x` had its outputs and its imports judged in `aDebugx`, while msbuild leaves the name as it is (measured). A variable redefined in the IDE with macros inside is still expanded, as the IDE does.
- `delphi_designer set` no longer refuses a sound value with `DSGN-158` ("the form would not open") when the IDE's form reader was stopped for time instead of judging it: a renderer that ran out of time judged nothing, and the value is now written with `readerNote` saying it was not judged, as when the reader could not be asked.
- A conversion of a form (`to-text`, `to-binary`, reading a binary `.dfm`) stopped by the renderer's own budget says it was the converter's time, not that something in the form waits.
- `delphi_designer layout` on an FMX form gives a control of the form its own line, not the line of a control with the same name inside an inline frame that comes before it.
- The rows of a batch (`edits`) and a few other echoes no longer cut a character in two: an emoji at the cut left half of it in the answer.
- A line of a file quoted in a warning or a refusal is cut at 120 characters, and says so with `...`. The checks of a form (`delphi_designer lint`, and the warnings `delphi_edit` gives after writing a form) quoted it whole, a 300-character line of data included, and so did the refusal of a method for a class with no body or on one line, `delphi_rename_symbol`'s warning about a qualified header and the out-of-range `character` of the language tools; the quotes that were already cut, a parser error or a use that stops a delete, were cut without saying it.
- `delphi_changeset stage` takes `ops` encoded twice (a JSON string holding the list), as `edits` already did.
- `vault_append` finds an `anchor` of several lines sent with Windows line breaks; it never matched, while `vault_patch` already took them.
- A project in a folder whose name has a comma builds when the build supplies its `.dcu` folder: msbuild split the value at the comma.
- A first load of the IDE's design packages answers before an MCP client gives up, and says it was the packages. Under Microsoft Defender it can take more than a minute once (each package it has not seen is checked), and the renderer went on until its 60 s, past what many clients wait, to answer `RENDER-007`, which then said "repeat" and also "something in the form waits". Now loading the packages has a budget of its own, 50 s, and a renderer still loading them answers `RENDER-027` with how many it loaded and the one it was on, so a package that hangs while it loads is named instead of asking for one repeat after another; repeating the call goes on from there (measured on a 4-core VM, three times with new bytes: 50 s and then 17 to 20 s, against 69 s in one go). `RENDER-007` is left for a form that does not finish, and when the server itself stops a renderer it says which phase it was in (`DSGN-187` while loading packages, `DSGN-062` after).

- `delphi_test`'s `filter` reaches the DUnitX runner as a Delphi program reads its command line, and one with a double quote is refused before anything runs (`TEST-037`). The runner's line was composed by the rules of the C runtime: a double quote closed the filter and what followed it became other options of the runner, and a final backslash arrived doubled.
- Lists of folders and files no longer lose one of two names the disk tells apart. `compilesAgainst` in `delphi_projects`, the IDE's profiles and SDKs in `delphi_paserver profiles`, the projects `delphi_references` adds to its search and the PAServer installers were sorted lists compared with the user's locale, which takes `Strasse` and `Straße`, or a name with a soft hyphen, for one: the second went missing. They now compare names as NTFS does.
- A folder marked shared (`SharedFolders`) whose name has a letter that is not ASCII is shared whatever the case of that letter, as NTFS compares two names: a confined agent was refused it when the case differed.
- `delphi_workspace` names the server's account as Windows does, from the process's own identity. The domain came from `USERDOMAIN`, which whoever starts the process sets.
- `delphi_test` copies into its container a folder next to the test whose name differs from the server's temporary folder in a character the user's locale takes for the same one (a small hyphen for its hyphen). The copy compared the name with the locale, while NTFS keeps the two apart, so the test did not find that folder.
- `delphi_list` and `delphi_search` hide only the server's own trash, `__delphi-patch`. A second name, the copies folder of a tool that is not this server, was hidden as trash, while every other tool read, wrote and deleted in it as in any folder.
- A file's extension is judged as NTFS compares names. With the user's locale, a name ending in `.pa` and a modifier letter s was taken for a Pascal source (`delphi_textedit` refused it as a Delphi file) and one ending in `.dpr`, a modifier letter O and `j` for a project file (refused with `EDIT-128`); the same judge decided what `adduses`, `removeuses` and `check-binding` take as a unit and what `delphi_test` leaves out of its copy.

- The renderer's own time limit comes from the call's. `delphi_designer layout` waited 30 s for it, but the renderer was told 60 s, and 50 s for the IDE's packages, so its watcher never spoke and the server stopped it without the reason. On a VCL form, `layout` now waits 45 s and the renderer gets 30 s for both (an FMX form's `layout` keeps a preview's time: its boxes come only from the renderer; its `insert` and `set parent=` get the 45 s): with 30 s in all it would get 15, and loading the 110 design packages of a real machine, already checked by its antivirus, took 12.6 of its 13.2 s. A preview keeps 60 s and 50 s. A call that renders again with forms brought from other folders gives each new round what is left of its time, not all of it again.

- `delphi_designer layout` knows what a container does with its children by its class's ancestry, in that framework's class table, not by a list of names that mixed VCL and FMX. Two overlapping buttons inside a VCL `TTabControl`, which has one area, were not reported, because FMX's `TTabControl` has pages; the items of an FMX `TListBox` that do not fit were reported as sticking out and not visible, although they scroll (also on `insert`); a `TMemo`, `TGrid`, `TPresentedVertScrollBox`, `TGridPanelLayout` or a component derived from one was not recognized. The `Align` a VCL class does not write is the one its source redeclares with `default`: `TActionToolBar`, `TActionMainMenuBar`, `TFormTabsBar` and `TCategoryPanelGroup` were missing, and `TCoolBar` and `TControlBar`, which do not redeclare it, were taken as `alTop`.

- The style converter `delphi_styles` uses (`build`, `lint`, `set`, the platform defaults) runs inside a Windows container of its own, on a copy of the style in a folder of that call, as the form renderers do. It ran outside any container, reading the agent's file directly, and `build` ran it in the agent's folder: a converter that wrote a file there did it. Its output now carries a protocol number, like the renderers' (`STYLE-066` when a converter of another version answers; `STYLE-065` when its container cannot be prepared), and when it does not answer, the server's log says why.
- When the shared folder of the renderers' packages could not be prepared, the call that asked for it could release the folder from under another call still using it.

- `DelphiLspMcp.exe --install` (or `--uninstall`) says that the Windows service installer reads `/install` or `-install`, instead of installing nothing in silence: the server took the three spellings of a mode, but the installer only reads those two.

- The form renderer loads an IDE package registered with any of the IDE's macros: it knew `$(BDS)`, `$(BDSBIN)` and `$(BDSCOMMONDIR)` by hand, so a package under `$(BDSCatalogRepository)` or `$(BDSUSERDIR)` (GetIt's, the user's) came out as missing. An SDK's sysroot and libraries take every IDE macro too, `$(BDSPLATFORMSDKSDIR)` among them, from the same table.

- With `$(BDSLIB)` redefined in the IDE's Environment Variables, the language server's library folder and the package names `delphi_build` suggests for a package (`requiresSuggested`) come from that folder, as msbuild takes it: both were composed from the IDE's root.

- With `$(BDSPLATFORMSDKSDIR)` redefined in the IDE's Environment Variables through another macro (`$(BDSUSERDIR)\SDKs`), the folder of the SDKs (where `delphi_paserver get-sdk` puts a sysroot, and where a profile's SDK is looked for) is the one it names, expanded by the IDE's macro table as every other path is. It fell back to the folder of the SDKs already registered, or to the default one, while that table said the redefined one.

- The two Linux binaries in `node\` no longer carry the Windows user name of the machine that built them: the Linux linker records the path of its temporary file, and with the profile's `%TEMP%` that path named the user. `BuildGroup.bat` builds with a temporary folder of its own, and the release gate refuses a package where any member carries that name; the versioned sources no longer name it either.

- `delphi_git diff` and `show` return the line of the source that git writes after a hunk header (`@@ -7,4 +7,4 @@ procedure X;`) and, with `format=words`, every line of a hunk as they are on disk: the drive masker rewrote them as server paths (`'Z:\x'` came back `'srv0:\x'`), as it did with the `+` and `-` lines before 1.9.0. A hunk is content from its `@@` to the next file, commit or note of the tool.
